# Abstract # {- .unlisted}

This paper is a response to the IE-133, Irish NB concerns on memory allocation with senders/receivers.

# The concern

The Irish NB provided the following comment during C\++26 ballot voting:

> The Irish NB did not reach consensus on senders/receivers. Some concerns:
>
> • Senders/receivers allocate implicitly using std::allocator, and a task's default task_scheduler can allocate using a default allocator even when the task is given an allocator.
>
> • Parallel scheduler backends get storage of unspecified size and no guaranteed allocator, so may allocate per operation.
> 
> This is unsuitable where allocation must be controlled, such as on embedded platforms.
>
> The earlier version, P2300R10, had none of these issues.
